# 支付业务需求

## 1. 文档目的

本文档集是支付业务的长期事实来源，用于约束业务范围、术语、规则和可判定结果。文档只描述业务现在应当如何运作，不保存历史版本，也不预设任何实现方式。

所有规则使用稳定编号 `PAY-BR-*`，所有验收场景使用稳定编号 `PAY-AC-*`。编号一经发布不复用；规则失效时保留编号并标记替代关系。

## 2. 业务愿景

为中小型线上商户提供一条可解释、可追踪、可核对的资金处理链路：

1. 商户为一笔业务订单发起支付；
2. 平台选择可用支付渠道并记录每次支付尝试；
3. 平台接收渠道结果，识别重复、迟到和矛盾通知；
4. 已成功支付的款项可以按规则发起一次或多次退款；
5. 平台按渠道账单核对支付与退款事实；
6. 平台按结算周期汇总商户应收、退款扣减和手续费，形成可确认的结算结果。

首期成功标准不是覆盖所有支付产品，而是把单币种交易从支付到结算的完整资金事实闭环说明清楚，并让关键异常具有明确处置结果。

## 3. 首期范围

### 3.1 范围内

- 商户创建支付及幂等重试；
- 支付渠道选择和多次支付尝试；
- 支付成功、失败、关闭及结果待确认；
- 渠道通知的验真、去重、乱序与迟到处理；
- 全额退款和多次部分退款；
- 退款成功、失败及结果待确认；
- 每日支付与退款对账；
- 平台账与渠道账的金额、状态、单边记录差异；
- 人工确认对账差异及留痕；
- 按商户和币种生成周期结算；
- 支付收入、退款扣减、手续费与净结算金额计算；
- 商户结算确认、支付执行失败与结果待确认；
- 面向商户的支付、退款和结算结果通知；
- 所有影响资金事实的操作可追踪、可解释。

### 3.2 参与者

| 参与者 | 责任 |
|---|---|
| 商户系统 | 创建支付、查询结果、申请退款、接收结果通知 |
| 付款人 | 选择支付方式并在渠道侧完成付款 |
| 商户操作员 | 查看本商户交易、发起退款、确认业务信息 |
| 平台运营人员 | 处理结果待确认、对账差异和异常结算 |
| 平台财务人员 | 复核对账结果、确认结算、处理资金异常 |
| 支付渠道 | 接受支付或退款请求，返回同步结果和异步通知，提供账单 |
| 结算执行方 | 接收结算指令并返回执行结果 |
| 时间 | 触发支付到期、日终对账、周期结算和异常升级 |

### 3.3 上下文边界

| 边界 | 所拥有的业务事实 | 不负责的事项 |
|---|---|---|
| 支付受理 | 支付单、支付尝试、支付状态、渠道结果 | 商户订单履约、渠道内部清算 |
| 退款处理 | 退款单、累计退款额、退款状态 | 售后审批依据、商品退货 |
| 对账处理 | 对账批次、对账明细、差异分类、处置结论 | 修改渠道账单、替代财务总账 |
| 商户结算 | 结算单、结算明细、手续费、净结算额、执行结果 | 税务申报、银行内部转账账务 |
| 商户与渠道配置 | 商户身份、渠道签约、费率、路由资格、结算周期 | 商户注册审核、渠道内部配置 |

跨边界只交换稳定业务身份和已经确认的业务事实。任何边界不得直接改写另一个边界拥有的历史事实。

### 3.4 上下文关系

```text
商户系统 ──创建支付、申请退款──> 支付受理、退款处理
支付受理、退款处理 <──支付与退款结果──> 支付渠道
支付受理、退款处理 ──资金事实──> 对账处理、商户结算
支付渠道 ──日账单──> 对账处理
对账处理 ──匹配或阻断结论──> 商户结算
商户与渠道配置 ──资格、费率、周期──> 支付受理、商户结算
商户结算 <──执行结果──> 结算执行方
```

支付、退款、对账和结算可以协作，但各自保留所拥有的历史事实。跨边界纠错通过新增确认、差异或调整事实完成，不通过直接修改上游记录完成。

## 4. 首期非目标

- 不提供银行卡收单网络、电子钱包或银行核心能力；
- 不实现真实资金托管、备付金管理和会计总账；
- 不支持跨币种支付、换汇或汇率损益；
- 不支持分账、分润、多级代理或平台抽佣网络；
- 不支持订阅扣款、预授权、撤销预授权；
- 不支持拒付、争议、仲裁和欺诈调查；
- 不支持税务发票、代扣代缴和监管报送；
- 不实现商户开户、身份审核和授信；
- 不承诺真实渠道协议的全部字段和安全细节；
- 不允许通过删除交易记录纠正业务错误；
- 不以历史兼容为目标，只维护当前业务规则。

## 6. 关键待确认假设

以下假设用于控制首期范围，在进入实现前必须逐项确认：

1. 每笔支付只允许一个币种，且支付、退款、对账、结算全链路币种一致；
2. 首期以商户订单号标识外部业务，但不管理订单内容和履约状态；
3. 支付到期时间由创建支付时确定，到期后原则上不再主动发起新尝试；
4. 同一支付允许多次渠道尝试，但最多只能接受一个最终成功结果；
5. 退款需要商户操作员发起，不包含消费者自助退款审批；
6. 商户是否允许退款、单笔上限和退款期限由商户配置决定；
7. 对账以渠道提供的不可变日账单为外部事实来源，但差异结论不自动覆盖平台交易事实；
8. 商户结算按商户和币种分别生成，不跨商户、不跨币种合并；
9. 首期结算周期至少支持日结，是否加入周结由业务评审决定；
10. 结算执行结果可能迟到或重复，未知结果不得当作失败后直接重复付款；
11. 金额最小单位及小数位遵循币种定义，首期可只启用人民币；
12. 费率和固定手续费在支付成功时形成快照，后续配置变化不追溯修改已有交易；
13. 支付、退款、对账和结算证据需要保留多长时间；
14. 支付受理、渠道结果收敛、商户通知、日终对账和结算分别需要满足什么业务时限。
