# 支付到结算生命周期

## 1. 支付生命周期

### 1.1 创建

商户提交商户订单号、金额、币种、幂等键、支付方式和必要的返回信息。平台完成商户身份、金额格式、币种、订单号和幂等性检查后创建支付单。

创建成功只表示收款意图被接受，不表示已经付款。

### 1.2 状态

```text
待支付
  ├─ 发起尝试 ─→ 处理中
  │                 ├─ 确认成功 ─→ 支付成功
  │                 ├─ 确认失败 ─→ 待支付或支付失败
  │                 └─ 无法判断 ─→ 结果待确认
  ├─ 到期 ─────────→ 已关闭
  └─ 明确不可继续 ─→ 支付失败

结果待确认
  ├─ 确认成功 ─────→ 支付成功
  ├─ 确认失败 ─────→ 待支付或支付失败
  └─ 超过核对期限 ─→ 人工核对
```

“确认失败”是否回到待支付取决于支付是否到期、失败是否可重试以及是否仍有可用渠道。支付成功、支付失败、已关闭是业务终态，但迟到或矛盾渠道结果仍须保留并进入核对。

### 1.3 主路径

1. 商户以稳定幂等键创建支付；
2. 平台从符合商户签约、币种、金额和支付方式的渠道中选择一个；
3. 创建支付尝试并向渠道发起付款；
4. 渠道受理后，支付进入处理中或结果待确认；
5. 有效成功通知到达后，记录渠道交易号和成功时间；
6. 支付成功事实只形成一次；
7. 平台通知商户，通知失败可重复发送；
8. 成功支付进入对账和后续结算范围。

### 1.4 多次尝试

- 一次失败的支付尝试不等于支付单必然失败；
- 每次尝试必须有独立身份、渠道和时间；
- 已经确认成功后不得再主动发起尝试；
- 两个尝试都返回成功属于重大矛盾，必须冻结自动结算并人工核对；
- 重试不得改变支付金额、币种和商户订单号。

### 1.5 超时、重复与迟到

- 到期时仍为待支付且没有未决尝试，支付可以关闭；
- 到期时存在处理中或结果待确认的尝试，不得直接认定失败，应先核对；
- 重复的相同通知只确认一次，但记录接收次数和时间；
- 已关闭支付收到有效成功通知时，记录迟到成功并进入人工核对；
- 已成功支付收到失败通知时，不撤销成功事实，记录矛盾证据；
- 来源无法验证、身份不匹配或金额不符的通知不得推动状态。

## 2. 退款生命周期

### 2.1 前提

只有已确认成功的支付可以申请退款。退款申请必须指定退款金额、原因、商户退款号和幂等键。

### 2.2 状态

```text
已申请
  ├─ 校验通过 ─→ 处理中
  │                ├─ 确认成功 ─→ 退款成功
  │                ├─ 确认失败 ─→ 退款失败
  │                └─ 无法判断 ─→ 结果待确认
  └─ 校验不通过 ─→ 已拒绝

结果待确认
  ├─ 确认成功 ─→ 退款成功
  ├─ 确认失败 ─→ 退款失败
  └─ 超过核对期限 → 人工核对
```

### 2.3 主路径

1. 商户提交退款申请；
2. 平台验证原支付、币种、退款期限和可退款金额；
3. 合法申请立即占用相应可退款金额，避免并发超退；
4. 平台向原支付对应渠道发起退款；
5. 渠道确认成功后形成退款成功事实；
6. 失败或被拒绝时释放占用金额；
7. 退款结果参与后续对账和商户结算。

### 2.4 异常与补偿

- 同一商户退款号重复提交且内容一致时返回同一退款结果；
- 同一商户退款号内容不一致时拒绝，并提示幂等冲突；
- 渠道已成功但平台未知时，通过渠道通知、主动核对或对账收敛；
- 平台已记录成功但渠道账单缺失时，不自动撤销，生成对账差异；
- 退款成功后原则上不可逆；错误退款通过独立业务处置，不改写原退款事实；
- 多笔并发退款的申请金额加总不得超过可退款金额。

## 3. 对账生命周期

### 3.1 范围

每个对账批次唯一确定：渠道、币种、对账日。批次核对该范围内的支付成功、退款成功及渠道账单记录。

### 3.2 状态

```text
待开始 → 获取账单 → 核对中
                    ├─ 无差异 ─→ 已完成
                    ├─ 有差异 ─→ 待处置 → 已完成
                    └─ 账单不可用 → 获取失败 → 重试或人工处理
```

### 3.3 差异分类

- 完全匹配；
- 平台单边；
- 渠道单边；
- 金额差异；
- 币种差异；
- 状态差异；
- 重复渠道记录；
- 无法关联。

### 3.4 处置原则

- 对账重跑不得重复形成有效差异；
- 原始平台事实和原始渠道记录不可被处置动作覆盖；
- 每项差异必须记录负责人、证据、结论和完成时间；
- 确认平台遗漏的成功事实时，应通过专门的补录确认过程形成新事实；
- 无法确认的差异不得进入自动结算；
- 对账完成意味着所有明细已匹配或已有明确处置结论，不意味着双方原始记录完全相同。

## 4. 商户结算生命周期

### 4.1 形成范围

结算单按商户、币种和结算周期生成。只有已经成功、处于结算周期内、未被其他结算单计入且不存在阻断差异的业务事实可以进入结算。

### 4.2 状态

```text
准备中 → 待复核
          ├─ 退回调整 ─→ 准备中
          └─ 确认 ─────→ 待执行
                           ├─ 执行成功 ─→ 已结算
                           ├─ 明确失败 ─→ 执行失败
                           └─ 无法判断 ─→ 结果待确认

结果待确认
  ├─ 确认成功 ─→ 已结算
  ├─ 确认失败 ─→ 执行失败
  └─ 超过期限 ─→ 人工核对
```

### 4.3 金额构成

```text
支付收入合计
- 退款扣减合计
- 手续费合计
+ 已确认调整合计
= 净结算金额
```

每一项必须有独立结算明细，并能追溯到支付、退款、费用规则或差异处置。

### 4.4 重复与未知结果

- 同一商户、币种和周期不得生成两个同时有效的结算单；
- 同一支付或退款不得被两个已确认结算单重复计入；
- 结算执行请求重复发送时必须携带同一业务身份；
- 执行结果未知时不得新建另一笔等额结算规避未知状态；
- 收到重复成功结果只确认一次；
- 收到成功与失败矛盾结果时冻结后续自动处理并人工核对。

## 5. 全链路追踪

对于任意一笔支付，应能回答：

- 谁在何时以哪个商户订单号创建；
- 经历过哪些支付尝试及渠道结果；
- 哪些通知被接受、拒绝、判定为重复或迟到；
- 发生过哪些退款以及累计成功退款金额；
- 被哪些对账批次核对，是否出现差异以及如何处置；
- 被哪些结算明细计入，手续费和净额如何计算；
- 关键人工动作由谁完成、依据是什么。

## 6. 外部业务契约语义

| 业务交换 | 必须携带的业务身份与事实 | 重复、迟到和失败语义 |
|---|---|---|
| 商户创建支付 | 商户、商户订单号、幂等键、金额、币种、支付期限、支付方式 | 相同意图返回原结果；同一幂等键内容冲突必须拒绝 |
| 渠道支付结果 | 渠道、支付尝试关联、渠道交易号、通知身份、金额、币种、结果、业务发生时间 | 重复结果不重复形成资金效果；未知、迟到或矛盾结果必须核对 |
| 商户申请退款 | 商户、商户退款号、原支付号、金额、币种、原因 | 相同内容返回原结果；冲突内容、超额或超期申请必须拒绝 |
| 渠道退款结果 | 渠道、退款关联、原渠道交易号、渠道退款号、通知身份、金额、币种、结果、业务发生时间 | 重复结果不重复占用或释放额度；未知结果继续占用额度 |
| 渠道日账单 | 渠道、币种、对账日、账单身份、记录身份、交易类型、金额、币种、状态、业务发生时间 | 同一账单可安全重跑；修订账单必须以新身份进入，不覆盖旧证据 |
| 商户结算执行结果 | 结算单、执行身份、金额、币种、结果、业务发生时间 | 未知结果禁止换身份重付；重复成功不产生第二次结算 |

任何外部交换都必须能区分业务发生时间与平台接收时间。完整账户凭据和不必要的付款人敏感信息不属于业务交换内容，只允许使用稳定引用或必要的掩码信息。
