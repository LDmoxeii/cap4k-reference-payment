# 业务规则与不变量

## 1. 身份与幂等

<a id="pay-br-001"></a>
### PAY-BR-001 支付身份唯一

每笔支付具有平台支付号。在同一商户内，幂等键唯一标识一次创建支付意图。

<a id="pay-br-002"></a>
### PAY-BR-002 创建支付幂等

同一商户使用同一幂等键重复提交完全相同的内容时，必须得到同一支付结果；任一关键内容不同则判定为幂等冲突，不创建新支付。

关键内容至少包括商户订单号、金额、币种和支付方式。

<a id="pay-br-003"></a>
### PAY-BR-003 外部业务号约束

同一商户订单号可以因明确业务需要关联多笔支付，但首期默认只允许一笔未关闭或已成功支付。是否开放再次支付必须形成明确规则，不得依赖偶然状态。

<a id="pay-br-004"></a>
### PAY-BR-004 渠道结果去重

同一渠道、同一渠道通知号或可证明为同一结果的重复通知，只能推动业务状态一次，但每次接收都必须留下记录。

<a id="pay-br-005"></a>
### PAY-BR-005 退款身份唯一

同一商户内商户退款号唯一。相同退款号和相同内容重复提交时返回原结果；内容不一致时拒绝。

<a id="pay-br-006"></a>
### PAY-BR-006 结算身份唯一

同一商户、币种和结算周期最多存在一份有效结算单；作废后重建必须保留关联关系和原因。

## 2. 金额与币种

<a id="pay-br-010"></a>
### PAY-BR-010 金额必须有效

支付和退款金额必须大于零，并符合币种允许的小数位和最小计量单位。不得接受无法精确表示的金额。

<a id="pay-br-011"></a>
### PAY-BR-011 支付金额不可变

支付创建后，金额和币种不可更改。需要改变金额时必须关闭原支付并创建新的支付意图。

<a id="pay-br-012"></a>
### PAY-BR-012 全链路币种一致

支付尝试、退款、对账明细和结算明细的币种必须与源支付一致。首期不允许换汇或跨币种抵扣。

<a id="pay-br-013"></a>
### PAY-BR-013 金额计算精确

所有手续费、退款余额和结算金额以币种最小单位计算。涉及费率时先按约定公式计算，再按该币种的统一舍入方式处理。

<a id="pay-br-014"></a>
### PAY-BR-014 费用规则快照

支付成功时确定适用的费率、固定费用和舍入规则。配置的后续变化不得追溯修改已形成的费用事实。

<a id="pay-br-015"></a>
### PAY-BR-015 净结算恒等式

一份结算单必须始终满足：净结算金额等于支付收入合计减退款扣减合计、减手续费合计、加已确认调整合计。

## 3. 支付规则

<a id="pay-br-020"></a>
### PAY-BR-020 只有合格商户可以创建支付

商户必须处于允许收款状态，且至少有一个符合币种、金额和支付方式要求的有效渠道配置。

<a id="pay-br-021"></a>
### PAY-BR-021 支付尝试独立留痕

每次向渠道发起付款都形成独立支付尝试，记录尝试身份、渠道、发起时间、状态及渠道结果。不得覆盖前一次尝试。

<a id="pay-br-022"></a>
### PAY-BR-022 支付最多成功一次

一笔支付只能形成一个被平台接受的成功事实。多个尝试成功属于矛盾结果，必须阻断自动结算并进入人工核对。

<a id="pay-br-023"></a>
### PAY-BR-023 成功事实不可回退

支付成功后，失败、关闭或取消通知不得把支付改回失败或关闭。冲突信息作为独立证据处理。

<a id="pay-br-024"></a>
### PAY-BR-024 未验证结果不得生效

来源无法验证、内容被篡改、商户或支付身份不匹配、金额或币种不一致的渠道结果不得推动支付状态。

<a id="pay-br-025"></a>
### PAY-BR-025 处理中不等于成功

渠道已受理、请求已发送、同步返回成功受理或跳转页已生成，都不能单独形成支付成功事实。

<a id="pay-br-026"></a>
### PAY-BR-026 到期处理

到期时没有未决尝试的待支付可以关闭。存在处理中或结果待确认尝试时，应先核对，不得仅因到期判定失败。

<a id="pay-br-027"></a>
### PAY-BR-027 迟到成功必须处置

已关闭或已失败支付收到经验证的成功结果时，不得静默忽略或自动覆盖终态，必须形成待人工核对事项并阻断相关自动结算。

<a id="pay-br-028"></a>
### PAY-BR-028 支付成功后停止新尝试

一旦支付成功，不得再主动创建新的支付尝试。已经在途的尝试仍需跟踪结果。

## 4. 退款规则

<a id="pay-br-030"></a>
### PAY-BR-030 退款来源有效

只有已确认成功的支付可以退款。退款必须关联原支付和原商户，且使用相同币种。

<a id="pay-br-031"></a>
### PAY-BR-031 可退款金额上限

任意时刻，已成功退款金额、处理中退款占用金额和新申请退款金额之和不得超过支付成功金额。

<a id="pay-br-032"></a>
### PAY-BR-032 并发退款防超退

多个退款同时申请时，只有在预占后仍满足可退款金额上限的申请可以继续；其他申请必须明确拒绝，不得先接受后产生负余额。

<a id="pay-br-033"></a>
### PAY-BR-033 退款期限

退款申请必须在商户约定期限内提出。超过期限默认拒绝；人工例外需要获授权并记录原因。

<a id="pay-br-034"></a>
### PAY-BR-034 退款失败释放占用

退款被拒绝或确认失败后，其占用金额必须释放。结果待确认期间继续占用，避免重复退款。

<a id="pay-br-035"></a>
### PAY-BR-035 退款成功不可改写

退款成功事实不可改回失败。后续矛盾结果进入人工核对。

<a id="pay-br-036"></a>
### PAY-BR-036 错误退款的处置

已经成功但业务上错误的退款不得删除或篡改。后续追偿或调整作为独立业务事实记录。

## 5. 对账规则

<a id="pay-br-040"></a>
### PAY-BR-040 对账范围唯一

每个有效对账批次唯一对应一个渠道、一个币种和一个对账日。相同范围重跑时不得产生重复有效结果。

<a id="pay-br-041"></a>
### PAY-BR-041 原始证据不可改写

平台交易事实、渠道原始账单记录和每次对账结果必须分别保存。差异处置不能覆盖任何一方的原始内容。

<a id="pay-br-042"></a>
### PAY-BR-042 逐笔关联优先

优先使用稳定渠道交易号关联；无法使用时可按经批准的组合条件辅助关联，但必须保留关联依据，禁止仅凭金额相同自动认定同一交易。

<a id="pay-br-043"></a>
### PAY-BR-043 差异必须分类

未完全匹配的记录至少归入平台单边、渠道单边、金额差异、币种差异、状态差异、重复渠道记录或无法关联之一。

<a id="pay-br-044"></a>
### PAY-BR-044 差异处置可审计

差异处置必须记录负责人、处置时间、证据、结论和产生的后续动作。不得用删除差异表示已解决。

<a id="pay-br-045"></a>
### PAY-BR-045 未决差异阻断结算

影响交易是否成功、金额或币种的未决差异不得进入自动结算。已明确不影响结算的差异必须记录判断依据。

<a id="pay-br-046"></a>
### PAY-BR-046 对账完成条件

对账批次只有在账单完整性通过、所有记录完成核对且每项差异已有明确处置结论时才能完成。

## 6. 商户结算规则

<a id="pay-br-050"></a>
### PAY-BR-050 结算范围隔离

结算按商户和币种隔离。不得把不同商户或不同币种的金额合并相抵。

<a id="pay-br-051"></a>
### PAY-BR-051 交易不得重复结算

同一支付收入、退款扣减或费用事实不得被两个已确认结算单重复计入。

<a id="pay-br-052"></a>
### PAY-BR-052 结算明细可追溯

每一条结算明细必须指向支付、退款、费用规则或已确认调整，并说明对净额的正负影响。

<a id="pay-br-053"></a>
### PAY-BR-053 结算确认后冻结构成

结算单确认后，周期、商户、币种和已有明细不可直接修改。后发现的差异进入后续周期调整，不改写已确认结算。

<a id="pay-br-054"></a>
### PAY-BR-054 执行结果未知时禁止重复付款

结算执行结果待确认时，不得创建另一份等额结算或使用新的执行身份重新付款。必须先核对原执行结果。

<a id="pay-br-055"></a>
### PAY-BR-055 结算成功不可回退

结算成功事实不可因迟到失败结果而回退。矛盾结果进入人工核对。

<a id="pay-br-056"></a>
### PAY-BR-056 负结算额处理

首期不自动执行负数结算。净结算金额小于零时，结算单转为待人工处理，并把欠款带入后续处理。具体追偿政策属于待确认事项。

## 7. 权限与留痕

<a id="pay-br-060"></a>
### PAY-BR-060 最小权限

商户只能查看和操作本商户的支付、退款与结算信息。平台人员只能执行其角色获授权的动作。

<a id="pay-br-061"></a>
### PAY-BR-061 敏感动作复核

人工确认迟到成功、补录资金事实、解除结算阻断和确认大额调整必须由具备相应权限的人员完成；是否需要双人复核由风险等级决定。

<a id="pay-br-062"></a>
### PAY-BR-062 资金事实不可删除

支付、退款、对账、结算及其外部证据不得通过删除纠错。更正必须追加原因、关联事实和操作人。

<a id="pay-br-063"></a>
### PAY-BR-063 时间一致

所有业务时间记录原始时间与业务时区。支付到期、对账日和结算周期使用统一业务时区计算。

<a id="pay-br-064"></a>
### PAY-BR-064 渠道配置退役不改写历史

已退役的渠道配置不得用于新的支付尝试，但历史支付尝试必须继续保留当时使用的渠道身份、费率和规则快照。配置退役不得删除或改写既有资金事实。

## 8. 待确认规则

以下问题尚未冻结，首期设计不得暗中代替业务方作答：

- PAY-BR-003 是否允许同一商户订单号在失败或关闭后再次支付；
- PAY-BR-026 未决支付尝试超过多长时间升级人工核对；
- PAY-BR-033 各商户退款期限和大额退款复核阈值；
- PAY-BR-046 渠道迟延提供账单时，对账完成的最长等待期限；
- PAY-BR-056 负结算额是顺延抵扣、商户补款还是两者并存；
- PAY-BR-061 哪些金额阈值必须双人复核；
- 日结之外是否首期支持周结；
- 商户通知失败重试到何时转人工处理。
