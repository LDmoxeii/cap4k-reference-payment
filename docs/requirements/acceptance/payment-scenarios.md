# 支付业务验收场景

每个场景只描述可观察的业务前提、动作和结果。示例金额均为人民币，除非场景另有说明。

## 1. 支付创建与处理

<a id="pay-ac-001"></a>
### PAY-AC-001 首次创建支付

**前提**：商户允许收款，存在适用于人民币和指定支付方式的有效渠道。

**当**：商户以幂等键 `K-001`、订单号 `O-001` 创建 100.00 元支付。

**则**：产生一笔金额为 100.00 元、币种为人民币的待支付记录，并返回稳定支付号；此时不得显示为已付款。

<a id="pay-ac-002"></a>
### PAY-AC-002 相同内容重复创建

**前提**：`K-001` 已成功创建 `O-001` 的 100.00 元支付。

**当**：商户再次提交完全相同的请求。

**则**：返回原支付号和当前结果，不产生第二笔支付。

<a id="pay-ac-003"></a>
### PAY-AC-003 幂等键冲突

**前提**：`K-001` 已用于 100.00 元支付。

**当**：商户使用 `K-001` 提交 120.00 元支付。

**则**：请求被明确拒绝，原支付金额仍为 100.00 元，不产生新支付。

<a id="pay-ac-004"></a>
### PAY-AC-004 渠道成功通知

**前提**：支付处于处理中，存在对应支付尝试。

**当**：收到来源可信、身份和金额均匹配的成功通知。

**则**：支付变为支付成功，记录渠道交易号和成功时间，并产生一次商户成功通知意图。

<a id="pay-ac-005"></a>
### PAY-AC-005 重复成功通知

**前提**：支付已因通知 `N-001` 成功。

**当**：同一通知重复到达三次。

**则**：支付仍只形成一个成功事实，不重复计算收入；能够看出通知总接收次数。

<a id="pay-ac-006"></a>
### PAY-AC-006 未验证通知

**前提**：支付处于处理中。

**当**：收到来源无法验证或金额不匹配的成功通知。

**则**：支付不变为成功，异常通知被保留并标记拒绝原因。

<a id="pay-ac-007"></a>
### PAY-AC-007 支付到期关闭

**前提**：支付已到期，仍为待支付，且不存在处理中或结果待确认的尝试。

**当**：到期检查发生。

**则**：支付变为已关闭，之后不再主动发起新尝试。

<a id="pay-ac-008"></a>
### PAY-AC-008 到期但结果未知

**前提**：支付已到期，但有一笔渠道尝试结果待确认。

**当**：到期检查发生。

**则**：支付不被直接判定失败或关闭；产生后续核对事项。

<a id="pay-ac-009"></a>
### PAY-AC-009 关闭后的迟到成功

**前提**：支付已关闭。

**当**：收到来源可信且金额匹配的渠道成功结果。

**则**：形成迟到成功核对事项，阻断该交易自动结算；不得静默丢弃结果，也不得在没有核对的情况下直接覆盖关闭事实。

<a id="pay-ac-010"></a>
### PAY-AC-010 两个尝试同时成功

**前提**：同一支付存在两个在途支付尝试。

**当**：两个尝试分别返回有效成功结果。

**则**：识别为矛盾结果，支付收入最多计入一次，交易被阻断自动结算并等待人工核对。

<a id="pay-ac-011"></a>
### PAY-AC-011 已成功订单不得重复收款

**前提**：商户订单 `O-001` 已存在一笔成功支付。

**当**：商户使用新的幂等键再次为同一订单创建同金额支付。

**则**：请求被拒绝，不创建第二笔可执行支付，并指出该订单已完成收款。

<a id="pay-ac-012"></a>
### PAY-AC-012 无效金额或币种被拒绝

**前提**：人民币只允许精确到分，且商户未开通美元收款。

**当**：商户提交金额为 0、金额精度超过分，或币种为美元的支付。

**则**：请求被拒绝，不产生支付记录或渠道尝试。

<a id="pay-ac-013"></a>
### PAY-AC-013 已创建支付的金额不可修改

**前提**：一笔 100.00 元支付已经创建。

**当**：商户尝试把金额修改为 120.00 元。

**则**：修改被拒绝，原支付金额和币种保持不变；如需新金额，必须形成新的支付意图。

<a id="pay-ac-014"></a>
### PAY-AC-014 费用规则使用成功时快照

**前提**：支付成功时适用费率为 0.60%，之后商户费率调整为 0.80%。

**当**：该支付进入商户结算。

**则**：手续费仍按支付成功时的 0.60% 及当时舍入规则计算，并能查看所用规则快照。

<a id="pay-ac-015"></a>
### PAY-AC-015 成功后的失败结果不回退支付

**前提**：支付已经由可信成功结果确认。

**当**：随后收到同一渠道交易的失败结果。

**则**：支付成功事实不回退，失败结果作为矛盾证据保留并产生核对事项。

<a id="pay-ac-016"></a>
### PAY-AC-016 渠道受理不等于支付成功

**前提**：渠道只确认请求已经受理，尚未给出最终资金结果。

**当**：平台接收该同步结果。

**则**：支付保持处理中或结果待确认，不形成成功收入、商户成功通知或结算候选。

<a id="pay-ac-017"></a>
### PAY-AC-017 支付成功后不再发起新尝试

**前提**：支付已经成功，且没有其他在途尝试。

**当**：系统准备再次选择渠道并发起付款。

**则**：新尝试被阻止，支付成功状态和既有尝试记录保持不变。

## 2. 退款

<a id="pay-ac-020"></a>
### PAY-AC-020 全额退款

**前提**：一笔 100.00 元支付已成功，尚无退款。

**当**：商户申请并最终成功退款 100.00 元。

**则**：成功退款累计额为 100.00 元，可退款金额为 0.00 元，该退款进入对账和结算扣减范围。

<a id="pay-ac-021"></a>
### PAY-AC-021 多次部分退款

**前提**：一笔 100.00 元支付已成功。

**当**：先后成功退款 30.00 元和 20.00 元。

**则**：成功退款累计额为 50.00 元，可退款金额为 50.00 元，两笔退款均可独立追踪。

<a id="pay-ac-022"></a>
### PAY-AC-022 超额退款被拒绝

**前提**：100.00 元支付已成功，已有 60.00 元成功退款。

**当**：商户申请退款 50.00 元。

**则**：申请被拒绝，可退款金额仍为 40.00 元，不向渠道发起退款。

<a id="pay-ac-023"></a>
### PAY-AC-023 并发退款防超退

**前提**：100.00 元支付的可退款金额为 60.00 元。

**当**：两笔各 40.00 元的退款申请几乎同时到达。

**则**：最多一笔进入处理；另一笔因余额不足被拒绝，处理中占用额与成功退款额之和不超过 100.00 元。

<a id="pay-ac-024"></a>
### PAY-AC-024 退款失败释放占用

**前提**：40.00 元退款处于处理中并占用可退款金额。

**当**：渠道明确确认退款失败。

**则**：退款变为失败，40.00 元占用被释放，可退款金额恢复。

<a id="pay-ac-025"></a>
### PAY-AC-025 退款结果待确认

**前提**：退款请求已送达渠道，但未得到确定结果。

**当**：等待期限届满。

**则**：退款保持结果待确认，相应金额继续占用，并产生核对事项；不得直接再次发起同额退款。

<a id="pay-ac-026"></a>
### PAY-AC-026 重复退款申请

**前提**：商户退款号 `R-001` 已用于 20.00 元退款。

**当**：再次以 `R-001` 提交相同内容。

**则**：返回原退款结果，不产生第二笔退款，也不重复占用金额。

<a id="pay-ac-027"></a>
### PAY-AC-027 非成功支付不得退款

**前提**：原支付处于处理中、结果待确认、失败或关闭状态。

**当**：商户为该支付申请退款。

**则**：申请被拒绝，不占用退款额度，也不向渠道发起退款。

<a id="pay-ac-028"></a>
### PAY-AC-028 超过退款期限的申请被拒绝

**前提**：原支付已成功，但已超过商户约定退款期限，且没有获授权例外。

**当**：商户申请退款。

**则**：申请被拒绝，说明超过退款期限，不改变可退款金额。

<a id="pay-ac-029"></a>
### PAY-AC-029 成功退款后的失败结果不回退退款

**前提**：退款已经由可信成功结果确认。

**当**：随后收到同一渠道退款的失败结果。

**则**：退款成功事实不回退，失败结果作为矛盾证据保留并产生核对事项。

## 3. 对账

<a id="pay-ac-040"></a>
### PAY-AC-040 完全匹配

**前提**：平台记录一笔 100.00 元支付成功，渠道日账单存在同渠道交易号、同币种、同金额、同状态记录。

**当**：执行该渠道、人民币、该对账日的核对。

**则**：明细判定为完全匹配，不产生差异。

<a id="pay-ac-041"></a>
### PAY-AC-041 平台单边

**前提**：平台记录一笔支付成功，渠道完整账单中不存在对应记录。

**当**：执行核对。

**则**：产生平台单边差异，保留平台和账单证据，交易在差异解决前不进入自动结算。

<a id="pay-ac-042"></a>
### PAY-AC-042 渠道单边

**前提**：渠道账单存在一笔成功交易，平台找不到对应支付或尝试。

**当**：执行核对。

**则**：产生渠道单边差异，不自动创建支付成功事实，进入人工调查。

<a id="pay-ac-043"></a>
### PAY-AC-043 金额差异

**前提**：平台成功金额为 100.00 元，渠道账单金额为 99.00 元，身份可关联。

**当**：执行核对。

**则**：产生金额差异，不用任一金额覆盖另一方，交易被阻断自动结算。

<a id="pay-ac-044"></a>
### PAY-AC-044 状态差异收敛

**前提**：平台记录结果待确认，渠道账单显示成功，且身份、金额和币种一致。

**当**：获授权人员核实渠道证据并确认补录。

**则**：形成可追踪的新确认事实，原结果待确认记录和渠道证据保留，差异结论记录操作人和时间。

<a id="pay-ac-045"></a>
### PAY-AC-045 对账重跑不重复

**前提**：某渠道、币种、对账日已经完成一次核对并形成三项差异。

**当**：因账单校验需要重跑相同范围。

**则**：不产生重复有效差异；能够区分两次运行及其结果变化。

<a id="pay-ac-046"></a>
### PAY-AC-046 未决差异阻断完成

**前提**：对账批次仍有一项金额差异没有处置结论。

**当**：尝试完成批次。

**则**：批次不能标记为已完成，并指出未决差异。

<a id="pay-ac-047"></a>
### PAY-AC-047 差异处置不改写原始证据

**前提**：平台金额与渠道账单金额不一致，获授权人员已经得到处置结论。

**当**：人员关闭该差异。

**则**：平台原始事实、渠道原始记录和最初差异仍可查看；处置结论以独立记录追加，并包含负责人、证据和完成时间。

## 4. 商户结算

<a id="pay-ac-060"></a>
### PAY-AC-060 正常结算计算

**前提**：结算周期内有 100.00 元和 50.00 元两笔可结算支付；有 20.00 元成功退款；手续费分别为 2.00 元和 1.00 元；无其他调整。

**当**：生成该商户人民币结算单。

**则**：支付收入合计为 150.00 元，退款扣减为 20.00 元，手续费为 3.00 元，净结算金额为 127.00 元；每项金额都能追溯到源事实。

<a id="pay-ac-061"></a>
### PAY-AC-061 未决差异不进入结算

**前提**：一笔支付存在影响成功状态的未决对账差异。

**当**：生成所在周期结算单。

**则**：该支付不进入自动结算，并明确显示阻断原因；其他无阻断交易可以按规则结算。

<a id="pay-ac-062"></a>
### PAY-AC-062 防止重复结算

**前提**：一笔支付已经计入已确认结算单。

**当**：再次生成后续周期结算单。

**则**：该支付不得再次作为收入计入。

<a id="pay-ac-063"></a>
### PAY-AC-063 结算执行成功

**前提**：127.00 元结算单已经确认并提交执行。

**当**：收到身份和金额匹配的成功结果。

**则**：结算单变为已结算，记录完成时间；重复成功结果不得形成第二次结算。

<a id="pay-ac-064"></a>
### PAY-AC-064 结算执行结果未知

**前提**：结算单已提交执行，但结果无法确定。

**当**：执行结果等待期限届满。

**则**：结算进入结果待确认，禁止用新身份重复支付，产生核对事项。

<a id="pay-ac-065"></a>
### PAY-AC-065 结算结果矛盾

**前提**：结算已收到有效成功结果。

**当**：随后收到同一执行身份的失败结果。

**则**：已结算事实不回退，记录矛盾证据并进入人工核对。

<a id="pay-ac-066"></a>
### PAY-AC-066 负结算额

**前提**：某周期退款扣减和费用超过支付收入，计算净结算金额为 -30.00 元。

**当**：生成结算单。

**则**：结算单进入待人工处理，不自动提交负数结算；完整保留金额构成。

<a id="pay-ac-067"></a>
### PAY-AC-067 结算确认后构成冻结

**前提**：结算单已经确认。

**当**：之后发现一笔应补计退款或费用调整。

**则**：已确认结算单的周期、明细和金额不被直接修改；新增影响进入后续周期调整或按规则作废重建。

<a id="pay-ac-068"></a>
### PAY-AC-068 同一周期不得存在两份有效结算单

**前提**：商户甲的人民币日结周期已经存在一份有效结算单。

**当**：再次为相同商户、币种和周期生成结算单。

**则**：不得产生第二份同时有效的结算单；若原单已作废，新单必须保留替代关系和原因。

## 5. 权限、通知与追踪

<a id="pay-ac-080"></a>
### PAY-AC-080 商户数据隔离

**前提**：商户甲和商户乙各有支付记录。

**当**：商户甲操作员查看支付详情或申请退款。

**则**：只能访问商户甲的记录；针对商户乙记录的操作被拒绝并留下安全记录。

<a id="pay-ac-081"></a>
### PAY-AC-081 商户通知失败重试

**前提**：支付已成功，首次向商户发送结果失败。

**当**：后续重试成功。

**则**：支付成功事实不重复产生；能够查看每次通知尝试及最终送达结果。

<a id="pay-ac-082"></a>
### PAY-AC-082 资金事实更正留痕

**前提**：获授权人员确认一项渠道单边记录实际属于漏记成功支付。

**当**：人员完成补录确认。

**则**：原始平台记录、渠道证据、确认原因、操作人和时间均可查看；不存在删除或覆盖原证据的行为。

<a id="pay-ac-083"></a>
### PAY-AC-083 支付全链路追踪

**前提**：一笔支付经历两次尝试、一次成功、一次部分退款、一项对账差异并进入商户结算。

**当**：按平台支付号查看业务轨迹。

**则**：能够按时间顺序看到创建、尝试、渠道结果、退款、对账及差异处置、结算明细和关键人员动作，且各环节金额能够相互核算。

<a id="pay-ac-084"></a>
### PAY-AC-084 退役渠道不再参与新支付

**前提**：某商户渠道配置曾被历史支付使用，现已退役。

**当**：商户创建新的支付。

**则**：退役渠道不参与新支付路由；历史支付仍能查看当时使用的渠道和费用规则快照。

<a id="pay-ac-085"></a>
### PAY-AC-085 业务时区决定日界线

**前提**：业务时区为亚洲/上海，一笔资金事实发生在该时区 23:59，另一笔发生在次日 00:01。

**当**：生成对账日和结算周期范围。

**则**：两笔事实分别归入对应业务日期，原始发生时间与业务时区均被保留。

<a id="pay-ac-086"></a>
### PAY-AC-086 敏感人工动作必须授权并留痕

**前提**：一项迟到成功需要解除结算阻断。

**当**：无权限人员尝试确认，随后获授权人员完成确认。

**则**：第一次操作被拒绝并留痕；第二次操作记录操作人、时间、理由和依据，后续影响可追踪。
