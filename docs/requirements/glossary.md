# 统一语言

本表中的术语在所有业务文档、示例数据和验收讨论中保持同义。不得用技术词汇替代业务概念。

| 术语 | 定义 | 边界说明 |
|---|---|---|
| 商户 | 使用平台收取其客户款项并接受结算的经营主体 | 一个商户可配置多个支付渠道 |
| 付款人 | 实际完成付款的自然人或组织 | 平台仅保留完成业务所需的最少身份信息 |
| 商户订单号 | 商户侧一笔业务订单的稳定标识 | 平台不拥有订单内容 |
| 支付单 | 商户针对一个订单和确定金额创建的收款意图 | 金额和币种创建后不可更改 |
| 支付尝试 | 针对同一支付单向某个渠道发起的一次独立付款过程 | 一个支付单可有多次尝试 |
| 幂等键 | 商户为一次业务意图提供的稳定去重标识 | 同一商户内唯一 |
| 渠道 | 实际受理支付或退款的外部支付服务 | 渠道内部状态不等于平台确认状态 |
| 渠道交易号 | 渠道赋予一次支付或退款的稳定标识 | 在对应渠道内唯一 |
| 渠道通知 | 渠道主动发送的支付或退款结果 | 必须先验证来源和完整性 |
| 同步结果 | 发起支付或退款时渠道立即返回的信息 | “已受理”不等于最终成功 |
| 结果待确认 | 已知操作发生，但尚不能确定最终成功或失败的状态 | 必须通过通知、查询或对账收敛 |
| 迟到通知 | 在平台已关闭或已形成不同终态后到达的有效渠道结果 | 不得静默忽略 |
| 矛盾结果 | 同一业务身份出现相互冲突的有效最终结果 | 进入人工核对，保留双方证据 |
| 退款单 | 针对一笔成功支付申请退回确定金额的业务记录 | 一笔支付可有多笔退款 |
| 可退款金额 | 支付成功金额减去已成功退款和已占用退款申请后的余额 | 不得为负数 |
| 部分退款 | 退款金额小于当前可退款金额的退款 | 可重复发生，累计受上限约束 |
| 对账日 | 渠道账单所覆盖的自然日 | 使用约定业务时区 |
| 对账批次 | 对一个渠道、一个币种、一个对账日执行的一次核对 | 同一范围可重跑，但有效结论唯一 |
| 对账明细 | 平台交易事实与渠道账单逐笔比较后的结果 | 包含匹配或差异分类 |
| 平台单边 | 平台存在交易事实，渠道账单不存在对应记录 | 需要调查请求或账单完整性 |
| 渠道单边 | 渠道账单存在记录，平台找不到对应交易 | 需要调查漏单或身份映射 |
| 金额差异 | 双方存在对应记录，但金额不同 | 不得自动取任一方金额覆盖 |
| 状态差异 | 双方金额一致或可比，但最终状态不同 | 需查明迟到结果或状态遗漏 |
| 差异处置 | 对差异进行调查、给出结论并记录证据的过程 | 处置不能删除原始事实 |
| 结算周期 | 汇总商户可结算交易的时间范围 | 以约定业务时区计算 |
| 商户结算单 | 对一个商户、一个币种、一个周期形成的应付汇总 | 周期范围不可重叠计入两次 |
| 结算明细 | 一笔支付收入、退款扣减或费用对结算额的影响 | 必须能追溯到源业务身份 |
| 手续费 | 根据支付事实和生效费率计算的商户成本 | 计算规则和舍入方式必须明确 |
| 净结算金额 | 成功支付收入减去退款扣减、手续费及已确认调整后的金额 | 可为零；负数处置首期需明确 |
| 结算执行 | 将已确认净结算金额交付给结算执行方的过程 | “已提交”不等于成功到账 |
| 业务时区 | 用于到期、对账日和结算周期边界的统一时区 | 首期默认亚洲/上海，需最终确认 |
| 资金事实 | 支付成功、退款成功、账单记录和结算结果等不可静默改写的事实 | 纠错使用新记录和处置结论 |
| 人工核对 | 由获授权人员基于证据处理未知或矛盾结果 | 所有动作必须留痕 |
